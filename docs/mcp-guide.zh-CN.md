# MCP 服务使用与验证

## 设置入口

打开 **设置 → MCP 服务**，或右侧 Agent 面板的 **MCP 服务** 按钮。

内置服务默认开启，提供 15 个工具：11 个绘图工具（含真实 TeX 预览和绘图 skill 参考库），以及项目上下文、论文文件读取、多文件修改提案和论文编译诊断。

“测试内置工具”会启动真实 Rust MCP 程序，完成协议握手、工具发现，再经本机桥接读取当前画布。测试不会修改画布。

## ACP 连接与模型选择

在 **设置 → Agent** 或聊天面板点击“连接 / 获取模型”。连接会初始化 ACP 并建立不带提示词、不挂载 MCP 的探测会话，读取 Agent 的模型配置选项；不会发送画布或论文上下文。模型列表由 Agent 提供，不是写死的 Claude/Codex 别名。未提供选择能力时显示“Agent 默认”，不虚构模型列表。

连接成功后可在设置或聊天面板选择模型。偏好按 Agent 分别持久化；下一轮建立真实会话后使用 `session/set_config_option` 应用模型，并核对 Agent 确认的当前值，然后才发送提示词。模型失效、不支持选择或切换失败会明确报错，不静默使用其他模型。选择“跟随 Agent 默认模型”可清除覆盖。

`cross-format conversion does not support context_management` 表示 Claude Code 当前模型网关拒绝该请求字段，不是画布或 MCP 格式错误。请为 Claude Code 配置原生 Anthropic 上游，或在内置 Pi 创建符合该网关真实 API 协议的渠道。ACP 连接成功不代表模型 API 可用；应用不会擅自删除上下文管理字段或重试付费请求。

## 添加外部服务

1. 添加服务，填写唯一标识。标识使用英文字母、数字、短横线和下划线，便于不同 Agent 生成兼容的工具名称。
2. 选择 stdio 或 Streamable HTTP。
3. stdio 填写已安装的可执行命令和 JSON 参数数组；包含空格或中文的文件路径作为单独参数保存。JavaScript 服务推荐使用 `node` 命令加入口文件参数。
4. HTTP 填写完整 MCP endpoint，鉴权信息放入敏感请求头。原生 HTTP 支持取决于当前 ACP Agent 的能力声明。
5. 保存后先测试，再启用。可将服务限定到指定 Agent。

新建及导入的服务默认关闭。服务配置会在下一轮消息建立 ACP 会话时传入 `mcpServers`，无需新建聊天，也不会修改用户 CLI 的全局配置。

外部测试仅进行握手与工具发现，不调用第三方业务工具。测试连接与 Agent 的运行时连接相互独立；测试通过不代表本轮已调用。会话挂载状态和实际工具调用分别显示。

第三方服务按自身权限运行。完整本机访问开关控制 ACP 原生文件与命令权限，不会把外部 MCP 服务统一变成只读服务。首版没有逐工具拦截。

## 敏感值

环境变量与请求头可选择：

- 系统凭据存储：配置文件只记录引用。
- 仅本次运行：敏感值只存在应用进程内存中，重启后需要重新填写。
- 普通值：明文保存在本机配置文件中，适合非敏感参数。

系统凭据存储不可用时会报告错误。需要临时使用时，在表单中明确选择“仅本次运行有效”并重新填写。

已保存的敏感值留空即保留；更改名称、保存方式或敏感标记时应重新填写。配置导出排除敏感变量与请求头，不导出凭据引用。

## 画布修改与停止

所有绘图 Agent 默认接入用户提供的 `tikz-diagram-reproduction` skill：先规划总览/细节分层、数据状态图形、语义配色和箭头语法，再生成代码。原创图可用局部 `\definecolor` 定义功能语义色板；明确要求严格期刊/黑白风格时再按对应规范约束。

`get_diagram_design_skill` 按主题读取原始设计指南或模板：`design`、`reproduction`、`swsa`、`gnn`、`mae`、`riemannian`。`macroIndex` 给出各宏的主题内行号；`startLine` 和 `lineCount` 可逐页读取，单页最多 160 行、16000 字符。完整模板库不会每轮注入，也不要求复制示例论文的方法、数据或整篇文档。

“复刻/还原/照图”任务优先保留参考图的形状、比例、配色和连线含义。`% @diagram-design {"mode":"reproduction","preserveColors":true,"preserveGeometry":true}` 记录此意图，后续精修不再自动套色、移动或改写标签，并使用保真预览。复杂宏/路径不承诺逐个节点可拖拽；真实视觉结果以 TeX 渲染为准。原 skill 中的 Python 测量脚本作为参考保留，未注册为 Agent 执行工具，不会声称做过未执行的像素测量。

绘图对话默认开启「视觉复核」：Agent 先生成待审提案，再用 `render_canvas_preview({proposalId})` 编译该提案，查看真实 PNG，按图修正后重新预览。工具不修改画布；未提供 `proposalId` 时渲染当前源码。需要桌面版（内置 TeX 引擎）和支持图片的模型；缺失时返回真实错误，不把 AST 评分当作视觉验证。

每轮最多渲染 3 个不同版本，同一源码、主题和编译配置复用结果。编译后会重新核对请求、画布版本和提案；已取消或过期结果不会回填。提案卡片可展开「真实 TeX 预览」。用户仍须点击应用。

Agent 输入框支持 Ctrl+V 粘贴截图和选择 PNG、JPEG、WebP 文件，显示可移除缩略图，也支持只发送图片。每条消息最多 4 张、每张原图不超过 10 MB，发送前缩小到最长边 1600 像素并压缩。图片会发给所选 Agent。ACP 在握手时检查图片输入能力；不支持时明确报错。为支持后续追问，ACP 每轮最多携带最近 4 张参考图；Pi 复用原生图像历史，仅在重建会话时补发最近参考图。

内置 MCP 工具只生成待审核提案，调用成功不代表画布已经修改。点击“应用”后才进入现有的撤销和保存链路。

每个请求绑定原始聊天、项目和画布。切换画布后，原请求的画布工具返回 `target_inactive`，不会转而操作当前画布。组件库及指定主题查询仍可使用。

论文工具绑定项目，而不是当前画布；同一项目内切换绘图、论文或章节不会中断论文工具。切换项目立即使旧请求失效，即使再切回来也不会恢复旧授权。向不同项目发送消息会创建新的项目对话，避免拼接其他项目的历史。

源码修改、撤销、重做或文档切换会改变版本。旧提案不能覆盖新源码；请回到原画布重新生成提案。撤回提案也会检查是否存在后续修改。

运行期间可点击右下角“停止”。关闭窗口、取消请求或结束本轮会话会撤销对应桥接授权；关闭内置服务会立即撤销当前内置工具授权。外部服务的启停和配置修改从下一轮生效。

## 论文协作与审阅

绘图和论文工作区共用右侧项目 Agent。论文模式会附加当前文件、文件列表、未保存标记及当前章节的有限长度内容；不再注入强制返回单个 `tikzpicture` 的绘图规则。

| 工具 | 功能 |
| --- | --- |
| `get_project_context` | 获取项目文件列表、活动章节、画布身份、论文版本与编译状态 |
| `read_project_file` | 读取已列出的项目文件，优先使用编辑器内容（包括未保存修改），不会切换当前编辑器标签 |
| `propose_project_patch` | 将 1–20 个现有 `.tex/.bib/.sty/.cls` 文件的修改合并为待审核修改集 |
| `get_paper_diagnostics` | 读取最近一次用户触发的编译结果、真实日志及版本过期标记；不启动编译 |

Agent 必须先逐文件读取，再提交对应 `sourceHash` 与 `paperRevision`。提案不会写文件，且会拒绝跨项目、路径穿越、重复路径和过期版本。`.tikz` 文件可读，但修改须走画布提案，避免两套写入链路冲突。本阶段不支持创建、删除或重命名论文文件。

修改卡片提供逐文件 Diff、整组应用、拒绝和整组撤回。应用前一次性检查所有文件；检查通过才同时更新编辑器，之后沿用项目的逐文件自动保存。**这不是磁盘级原子事务**；保存失败会保留脏文件，不能把“已应用到编辑器”当作保存成功。后续手动编辑会阻止旧提案覆盖或撤回。

桌面端可点击“应用并编译”：保存成功后调用本机 TeX，并将 PDF、诊断及版本交给论文预览和 Agent 共用。未应用提案不会参与编译；源码更新后旧诊断会标记过期。编译成功不代表已进行视觉验证。浏览器模式不连接本地 Agent 或执行 TeX，不生成模拟结果。

ACP 仍沿用每轮会话。可选的内置 Pi 后端已支持长驻会话，复用相同的内置项目工具与审阅机制；Pi 当前不连接第三方 MCP，不加载本机扩展，不受 ACP 的完整本机访问开关影响。草稿编译沙盒及自动修复循环尚未实现。详见 [Pi 运行时](pi-runtime.zh-CN.md)。

## 开发与打包

```sh
npm ci
npm run adapters:stage
npm run mcp:stage
npm run pi:stage
npm run test:pi
npm test
npm run test:mcp
npm run test:packaging
npm run build
cargo test --manifest-path src-tauri/Cargo.toml -j 2
```

`mcp:stage` 从 `crates/agentikz-mcp` 构建原生 stdio 程序，并生成当前目标对应的 Tauri sidecar。Tauri 开发和打包命令会自动执行此步骤。macOS universal 构建会分别构建两个架构并合并。

开发构建需要 Rust 1.88 或更新的稳定工具链。

协议程序采用锁定的官方 Rust SDK `rmcp`。应用内桥接只监听随机的本机回环端口，并使用每轮临时令牌；它不是可供第三方应用直接连接的公开 HTTP MCP 服务。

外部服务配置存放在应用数据目录的 `mcp/servers.json`。测试结果不会保存为永久连接状态。

## 首版范围

支持 stdio、Streamable HTTP、手动请求头鉴权、适用 Agent 选择、导入导出、工具发现、画布提案，以及项目级论文读取、修改审阅与共享编译诊断。

旧 SSE、OAuth 自动登录、逐工具授权、自动应用画布修改、公开隧道和其他客户端的独立接入配置后续扩展。
