# 运行链路与逻辑、性能优化

## 1. 运行思路

以 TikZ 源码为唯一文档事实来源，AST 是派生数据，不单独维护另一份可编辑图形模型：

```text
源码输入 / 属性修改 / 画布拖拽 / 接受 Agent 提案
  → 对源码进行局部补丁
  → Workspace Store 更新源码、解析 AST、维护撤销栈
  → 按需订阅的 React 组件绘制 SVG / KaTeX
  → Project Store 标脏，500 ms 防抖保存画布和同步 .tikz
```

论文编辑走独立的按文件保存链路；本地 TeX 编译是显式操作，不放在每次拖拽的热路径中。Agent 请求通过 ACP 发送上下文并接收流式回复，生成待确认的源码提案；接受提案后才进入上述文档更新链路。

主要状态边界：

- **Workspace Store**：当前图形、派生 AST、视图、选择和撤销历史。
- **Project Store**：项目路径、画布文件、论文文件缓存、保存和资源。
- **Agent Store**：对话、流式状态和待应用提案。
- **Settings Store**：持久化偏好，不应让偏好变化触发整个工作台重绘。

## 2. 本次优化

### 解析与拖拽热路径

- 原先每个源码 span 的起止行号都从文件开头重新扫描，元素增加时形成近似平方级成本。
- 改为每次解析只构建一次行起点索引，行号查询使用二分查找，保留原有字符位置和一基行号语义。索引只在本次解析中存活，不引入全局文档缓存。
- 多元素坐标补丁改为排序后分段拼接，避免每移动一个元素就复制整份源码。
- 批量移动和连线渲染使用 ID 索引；节点排序缓存到文档变化时才重算，拖动成员判断使用 Set。
- 坐标没有实际变化时，不重复发布状态或添加撤销快照；非有限坐标不会写进源码。

### React 更新边界

- 将组件中解构整个 store 的订阅改为字段选择器并进行浅比较，避免画布平移、自动保存或 Agent 状态影响不使用这些字段的组件。
- `LatexLabel` 使用组件级 memo，配合原有的公式 HTML memo，减少父级更新时不变标签的渲染工作。
- 文档、主题、撤销和切换画布使旧编译预览失效；内置预览也随图像资源加载和画布尺寸变化更新。

### 论文持久化

- 同一项目、同一文件的写入串行，不同文件仍可并行；相同内容的并发保存共用一次写入。
- 写入完成仅清除对应内容版本的脏状态，保存期间的新编辑仍保持待保存。
- 提供统一的 `saveAllDirtyPaperFiles`，持续排空保存期间产生的新编辑，供项目切换、论文编译和论文模式下的 Ctrl+S 使用。
- 项目变化递增工作区版本并清理缓存、定时器。旧读取、扫描和写入回调不能更新新项目，包含 A → B → A 的情况。
- 磁盘读取不会覆盖等待期间的新编辑；浏览器存储失败不会伪装成保存成功；原生读取失败不会悄悄切换成模拟文件系统。
- 宏样式内容未变且已保存时，不重复写盘。

### 编译链路

- 论文入口参数统一为后端要求的 `mainTexFile`，而不是被忽略的 `mainTexRelPath`。
- 编译前先保存图形、同步配图并排空论文修改；保存失败时停止编译。
- 预览和论文编译忽略过期结果，避免把旧文档或旧项目的输出显示到当前工作区。
- TeX 子进程有超时并配置超时后终止直接子进程：预览引擎和 SVG 转换各 60 秒，论文每次 TeX pass 120 秒，BibTeX 60 秒。
- 第一遍失败后不重复编译；后续 pass 的失败不再回退为前次成功状态。成功判定同时要求进程成功和非空 PDF，避免上次遗留 PDF 导致误报。
- 临时预览目录使用进程 ID、时间和原子序号，避免并发编译时目录名冲突。

## 3. 本地基准

2026-11-08，同机、同脚本；每组先预热 5 次，再取 15 次完整解析的中位耗时。样例包含不同坐标和标签的普通节点，不包含图表、公式渲染或磁盘 IO。

| 节点数 | 优化前 | 优化后（首次对照运行） |
| --- | ---: | ---: |
| 100 | 4.66 ms | 0.42 ms |
| 500 | 112.15 ms | 1.73 ms |
| 1000 | 465.01 ms | 3.24 ms |

执行 `npm run benchmark:parser` 可复测。该结果仅衡量解析，不代表端到端帧率或所有文档都能得到同样倍数的提升；构建和系统负载也会影响结果。

## 4. 验证与后续边界

新增测试覆盖源码 span 的 LF/CRLF、多行标签和非源码顺序访问，批量变长坐标补丁，编译预览失效，以及论文并发保存、跨项目过期回调、存储失败和切换前排空编辑。Rust 测试覆盖失败进程不能接受遗留 PDF。

后续可独立评估，未混入本次修改：

- 真实大文档的浏览器性能剖析，必要时再引入逐帧合并拖拽更新、解析 worker 或增量解析。
- Agent 流式 token 的按帧合并，以及超长会话的上下文预算。
- 原生文件遍历的增量扫描、文件监听与大图资源按字节预算缓存。
- 生产包的按需加载。目前仍有大 chunk 提示，不用提高警告阈值来掩盖。
- 真正的本地 TeX Live / BibTeX 集成测试；自动测试和浏览器预览不能替代完整桌面编译验证。
