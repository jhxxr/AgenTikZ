# 图片素材与论文插图流程

## 按钮含义

- **素材卡片 → 画布**：把图片作为图元加入当前画布，不改论文。PDF 不创建无法预览的画布占位图。
- **素材卡片 → 插入论文…**：预选这张素材，打开章节、图注、标签、栏宽和宽度设置。不会偷偷换成当前画布的 TikZ 图。
- **绘图顶部 → 插入当前配图**：保存当前非空画布与图源后插入论文；没有论文或画布为空时不可用，右侧箭头仍可打开选择窗口。
- **论文区 → 插入配图**：可以选择已有 TikZ 图源或导入 PDF/PNG/JPEG，不需要先打开画布。
- **仅插入**：保存后留在当前工作区。**插入并查看论文**：保存成功才跳转，并将源码光标定位至实际插入处。
- **复制代码**：只复制，不声称已经保存到论文。**同步宏包**只同步宏包，不声称同步了所有图源。

## 目标与保存

插图只能写入当前项目已有的 `.tex` 文件。空章节仍是章节，不会被复制的 `main.tex` 或整篇论文模板覆盖。读取章节不会先切换编辑器，也不会把另一个文件的旧光标用于新章节。

源码插入使用光标附近的安全行；若光标在导言区、命令参数、公式或其他环境内，则移至章节末尾或真实的 `\end{document}` 之前。注释、常见 verbatim 代码示例中的结束标记不参与定位。保留原文空白，不使用可能把 `$&` 等内容当作 JavaScript 替换符的字符串替换。

外部图片只检查并添加论文主文件所需的 `graphicx`，不会保存当前画布或生成 TikZ 宏包。TikZ 插图则显式保存对应 `.tikz` 和宏包；自动同步关闭时也会完成这次明确要求的图源导出，不改变自动同步偏好。

主文件、目标章节、图源与宏包的保存失败都会报告错误，不显示成功。已经更新的编辑器内容会作为脏文件保留，以便重试；这不是磁盘级多文件原子事务。重试会识别已经存在的插图，避免重复插入。

## 格式、标签与去重

- 直接论文插图支持 PDF、PNG、JPEG。SVG/WebP 可作为画布素材，但直接放入常规 TeX 论文前需转换；界面不会把不支持的格式当作可编译图片。
- 桌面端插入前检查确切的磁盘文件是否为非空、受支持的项目内文件，不会为了检查大 PDF 把它加载为预览 Data URL。浏览器检查虚拟项目内是否保留图片数据。
- 带空格或中文的文件名按实际路径引用，不擅自替换成另一个不存在的文件名。路径穿越、TeX 保留路径字符、非法标签及不在 `(0, 1]` 的宽度比例会被拒绝。
- 默认图注使用中性名称，不虚构“实验结果”等含义。手动图注保留 LaTeX 语法，未转义 `%` 和不平衡花括号会提示修正。
- 同一图片在同一目标章节默认只定位已有引用，不重新插入或覆盖原图注。勾选“允许重复”可明确增加一处引用。新标签会检查项目中已读取的所有 `.tex`，冲突时追加序号。
- 默认栏宽参考实际论文的显式单双栏设置，不再只按画布尺寸把单栏论文误判为双栏。

完整 LaTeX 文档不能直接 `\input` 成论文中的 TikZ 图。遇到这种源文件会提示使用单独的 `tikzpicture` 或导出的 PDF，而不是生成嵌套 `\documentclass` 的无效论文。

## 素材与生成图片

导入素材不再顺带把第一张外部图放进画布。同名导入追加序号，避免静默覆盖。素材刷新与导入/生成并发时，新素材不会被较早发出的扫描结果抹掉。

生成图片使用唯一名称或调用者明确要求的 `figures/assets/ai/*.png` 路径，不再重复覆盖默认 `ai_cutout.png`。处理后保存接口包含完整的节点、提示、provider、模型和真实尺寸信息，并校验 PNG 头部尺寸。图片登记使用正式的素材导入接口，不再调用参数不匹配的生成记录接口并吞掉错误。

生成结果无法解码、无画布处理能力、图片落盘失败时会明确失败，不生成假定为 512×512 的占位“成功”结果。切换项目后不会把旧任务结果写入新项目；切换画布或修改节点后不会偷偷覆盖当前节点。

## 验证边界

覆盖单元测试、Rust 文件检查/保存测试及浏览器交互验收。浏览器检查了“素材卡片选图 → 手填图注/标签 → 换素材/刷新 → 插入并定位 → 再次插入去重”，以及非法宽度禁用确认按钮。

插入/保存成功不等于 TeX 编译成功，更不等于科学内容已经核实。当前测试环境没有可用的 TeX 编译器，仍需在配置 TeX Live 的桌面端编译真实论文验收；图片服务商的付费生成请求不作为自动测试的一部分。
