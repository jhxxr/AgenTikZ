# 内置 Pi 项目 Agent

## 配置与使用

1. 使用 Tauri 桌面端，并安装 Node.js 22.19 或更新版本。无需安装 Pi CLI。
2. 打开设置 → Agent → 内置 Pi，添加渠道。预设只是填写起点；同一供应商或协议可添加多个渠道，分别命名。
3. 选择 API 协议、填写自定义 API 基础 URL，并点击“保存地址”。支持 OpenAI Chat Completions、OpenAI Responses、Anthropic Messages、Google Generative AI；兼容服务和中转使用其真实支持的协议。地址需保留 `/v1`、`/api/v1` 或 `/v1beta` 等前缀，不填写 `/chat/completions` 等请求路径。
4. 输入该渠道的 API Key，保存到系统凭据库；同一 provider 的不同渠道不共享凭据。模型 API 单独计费，不复用 CLI 登录。
5. 点击“获取渠道模型”，搜索并勾选所需模型后添加；也可直接输入模型 ID 手动添加，或检测运行时后从 SDK 目录选择参考条目。获取列表不会自动覆盖已配置模型，也不会把删除的模型自动加回。
6. 选择默认模型，可删除不需要的模型。核对图片输入、推理、上下文与最大输出长度；模型列表通常不包含这些完整信息，手动添加默认仅文本、无推理。配置推理强度后点击“使用此渠道与模型”，启用 AgenTikZ 内置 MCP 工具并发送任务。聊天面板可直接切换渠道与模型，各渠道记住默认模型。

“检测 Pi 运行时”只读取本地 SDK 模型目录；“获取渠道模型”会携带该渠道密钥请求模型列表，但不发送项目上下文、不进行模型推理。两者均不保证实际推理调用成功。实际任务才发送项目上下文。纯浏览器可编辑非敏感渠道设置，但保存密钥、获取模型和推理需要桌面端。

SDK 目录保留 Anthropic、OpenAI、Google、OpenRouter、Groq、Mistral、xAI 和 DeepSeek 的 API-key 模型参考。自定义渠道不要求模型存在于该目录，按用户指定的协议与模型能力注册到内存运行时，不会自动换渠道或回退到其他模型。OAuth、CLI 订阅登录、Azure/Vertex/Bedrock 等额外云认证仍不支持，不读取本机云账号作为回退。

模型获取使用所配置基础 URL 下的 `/models`（Anthropic 无 `/v1` 后缀时追加 `/v1/models`）。支持 Anthropic、Google 的有界分页；未提供列表接口的渠道请手动添加。密钥只放在请求头，列表请求不跟随重定向；对响应大小、模型数量、分页及请求时长设限，错误不会回显服务端响应正文。URL 只允许 HTTP(S)，禁止内嵌用户名、密码、查询参数和片段；明文 HTTP 仅应用于可信本地服务。

API Key 不写入 localStorage、项目文件或命令行参数；渠道列表和模型偏好可以持久化，但嵌套对象也仅保存明确允许的非敏感字段。Rust 按渠道 ID 从系统凭据库取出密钥，通过私有 stdin 交给 Pi 的内存凭据存储。保存或删除密钥会重置当前窗口的 Pi 进程。删除渠道先删除对应凭据；删除模型不删除渠道密钥。旧版单 provider 配置仍可运行，首次添加相同 provider 渠道时复用旧凭据 ID。凭据库不可用时明确失败，不降级为明文文件。

## 会话与任务

Pi SDK 固定为 `@earendil-works/pi-coding-agent@1.5.0`，npm 依赖树由 `runtime/pi/package-lock.json` 锁定。Rust 维护每个窗口的长驻 worker；正常多轮对话复用 SDK 的真实消息、工具调用和工具结果，而非重新拼接每轮完整历史。

会话按项目、聊天、渠道 ID / URL / 协议 / 模型配置、provider、模型、推理强度、密钥和工具清单隔离，最多保留 8 个会话，使用最近使用顺序淘汰。15 分钟空闲后下一轮会重建 worker。模型上下文压缩由 Pi SDK 管理。单任务限制为 24 个模型 turn 和 10 分钟；输出也有大小限制。

“停止”撤销当前请求的项目工具授权并结束当前 worker；下一轮新建运行时，仅恢复界面可见的聊天记录，不声称恢复旧工具历史。切换项目、关闭窗口、手动重置或进程失败也会使运行时失效。恢复提示区分“新会话”与“长驻会话已复用”。应用重启后不恢复内存会话；当前聊天记录本身也未实现持久化。

切换同一项目的绘图/论文视图不会重建 Pi 会话。每轮仍刷新最新上下文、提案审核状态和桥接令牌，历史工具结果不能作为最新文件版本使用。

## 工具与审阅

Pi 仅注册 AgenTikZ 清单中的 15 个工具：画布读取/诊断/提案/真实 TeX 预览、内置绘图 skill 参考库，以及论文读取/多文件提案/编译诊断。工具经过同一 Rust 本机桥接、前端版本/hash 校验、项目身份校验和审阅 UI。

没有内置 shell、read/write 文件工具、web 工具、个人插件、自动发现的 AGENTS.md、技能或可执行扩展。第三方 MCP、ACP 的“完整本机访问”、代理和 User-Agent 配置不应用于 Pi。外部 MCP 配置界面因此不提供 Pi 选择。

Pi 返回的代码块不会自动提升为画布修改，必须调用提案工具。自动模式下每次有效的工具修改立即写入编辑器，无需点击确认；手动模式保留审核、整组应用和拒绝。连续自动修改可在本轮结束后整组撤回；停止或错误不会回滚此前已应用的内容。桌面端可“应用并编译”。论文工具读取最近的编译诊断，不自主启动整篇论文编译。

绘图任务与 ACP 共用内置 `tikz-diagram-reproduction` 设计策略，按任务注入构图、图形选择、算子语义配色、复刻保真规则，以及最多两个相关论文参考族。需要细节时用 `get_diagram_design_skill` 逐页读取原始指南和四组宏模板；不会一次塞入完整模板库，也不提供执行原 Python 脚本的权限。

绘图开启「视觉复核」时，Pi 可使用 `render_canvas_preview` 编译待审草稿或已自动应用的配图，接收原生图片工具结果，按图修改再渲染；每轮最多 3 个不同版本，相同输入复用结果。手动模式保持待审核，自动模式立即应用有效修改，继续修改前重新读取最新源码、版本和 hash。文本模型会跳过图片渲染并明确报告未做视觉验证。

输入框支持粘贴或选择参考图片；仅接受支持图片输入的模型。图片以 SDK 原生 image block 传递，不拼成 base64 文本。正常会话只发送本轮新图；恢复会话时附带最近最多 4 张参考图。图片和聊天均只保留在当前应用内存中。

## 构建

```sh
npm ci
npm run pi:stage
npm run test:pi
npm test
npm run build
cargo test --manifest-path src-tauri/Cargo.toml
```

`pi:stage` 只在开发/构建时运行 `npm ci --ignore-scripts`，在临时资源目录完成真实 SDK 启动与模型目录检查，然后替换资源；失败时保留原资源。桌面构建会自动执行。运行中的应用不安装 npm 包。

Pi SDK 保留其完整依赖资源与许可证，独立于已有精简 ACP 适配器；当前大约增加 109 MiB 的未压缩资源（以实际安装依赖为准）。尚未对 Pi 做裁剪，不捆绑 Node 可执行文件。Tauri 资源目录为 `pi-runtime/`。

## 验证范围

`test:pi` 包含渠道模型获取、分页、认证头、重定向防泄露、隔离/取消/资源限制测试。真实 Pi SDK 对接本机测试服务，验证四种自定义 API 协议、相同模型 ID 在不同渠道使用各自地址和密钥，以及工具回合、流式输出与原生历史复用。测试服务仅用于测试，不进入产品运行时。

另有实际 worker 启动及模型目录检查；不会读取用户模型密钥或发起付费测试。真实服务商认证、计费模型行为仍需使用用户自己配置的服务验收。
